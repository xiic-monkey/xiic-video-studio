# 节点输出 → 输入兼容矩阵

这份矩阵是画布连线的唯一依据：能不能连、连上之后下游拿到什么，都按这里执行。
代码里的落点：

- 端口定义：`src/domain/nodes/definitions.ts`
- 类型兼容规则：`src/domain/graph/validate.ts` 的 `compatibleTypes`
- 输出取值：`src/domain/graph/output.ts` 的 `resolveNodeOutput` / `resolveInlineText`
- 运行期取值：`src/domain/run/prepare.ts`

## 1. 数据类型族

| 族 | 成员 | 说明 |
|---|---|---|
| 文本族 | `text`、`script`、`beat` | 都是「一段可以直接塞进提示词的文字」，彼此可连 |
| 图像族 | `image`、`frame` | `frame` 只是「当作首尾帧用的图」，与 `image` 等价 |
| 视频 | `video` | |
| 音频 | `audio` | |
| 任意 | `any` | 只有本地素材节点用；连线时按节点上的素材类型判定真实类型 |

### 明确不允许的连线

| 连线 | 结果 |
|---|---|
| 视频 → 任何图片输入 | 类型不匹配；需要先拆帧（拆帧结果作为参考图） |
| 音频 → 任何文本输入 | 类型不匹配 |
| 文本 / 剧本 / 节拍 → 任何图片、音频、视频输入 | 类型不匹配 |
| 本地素材（视频）→ 图片参考图 | 按素材实际类型判定，连线瞬间就拦下 |
| 图片节点同一「提示词」端口接两个来源 | 单输入端口只能接一个来源；「上下文」「参考」等多值端口才可以接多个 |

## 5. 剧本节点的取值规则

剧本节点是**内容节点**，输出不来自某次运行，而来自节点里写着的字段：

1. 「剧本」输出 = 节点正文；「节拍」输出 = 节点节拍。
2. 连给下游文本输入时，文本直接进入下游的提示词变量（按目标端口名，如 `prompt`、`context`、`idea`）。
3. 剧本节点现在可以运行（`text.chat`）：模型按「创作要求」+ 上游灵感输出
   `{"script": "...", "beats": [...]}`，运行成功后**回填**到正文与节拍字段，下游随即拿到新内容。
4. 模型没按 JSON 输出时按纯文本兜底：正文取全文，节拍留空（不猜）。
5. 剧本正文改了，下游的缓存键跟着变（按内容哈希），需要重新跑；剧本节点自身不会因为回填被判成「结果已过期」。

## 6. 本地素材节点的收紧

本地素材的输出端口声明为 `any`，因为素材类型是节点上的一个可改字段。
连线校验时按节点当前选的素材类型（图片 / 视频 / 音频）判定真实类型：

- 视频素材只能进「参考视频」；
- 图片素材可以进图片类输入和「首帧 / 尾帧」；
- 音频素材只能进「参考音频」。

改素材类型后，原来那条连线会在画布检查里报类型不匹配，需要重新连。
